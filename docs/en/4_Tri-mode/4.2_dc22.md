# 4.2 DC22 Tri-mode (work in progress)

22-key tri-mode numeric keypad · USB / Bluetooth / 2.4G

::: warning Work in progress
**The wired (USB) channel is verified on real hardware**: enumeration, typing, VIA remapping and saving to flash all work.

**The following are not yet verified on hardware, and specs / keymap may still change**: Bluetooth (BLE), 2.4G, low power, audio-reactive lighting.
:::

## 2. Shortcuts

Factory defaults. **All of them can be changed in VIA** (see section 6); changes persist across power loss.

Standard numpad: `0`~`9`, `.`, `/`, `*`, `-`, `+`, `Enter`, `NumLock`, `Home`, `End`, `PgUp`, `PgDn`, plus one `FN` key.

### 2.3 FN2 lighting layer (long-press P/)

A short press of `P/` is divide; **holding it for about 0.2 s** enters the FN2 layer. The lighting keys deliberately avoid the handiest FN-layer positions P1–P4 — those are reserved for mode switching.

## 3. USB / Bluetooth / 2.4G

In one sentence: **cable plugged in means USB; unplug and it returns to the last Bluetooth profile you used; once you switch manually it won't be pulled back.**

### 3.1 Automatic switching

The firmware switches on the VBUS **edge** — you don't need to press `FN + 4` in normal use:

| Event | Behavior |
| ---------------- | -------------------------------- |
| Plug in | Switches back to **USB** immediately and remembers the mode |
| Unplug while on USB | Returns to the **last used Bluetooth profile**; profile 1 if Bluetooth was never used |
| Unplug while not on USB (2.4G) | Stays put |

- **You can switch to Bluetooth with the cable plugged in**: after pressing `FN + 1/2/3` it won't be pulled back to USB.
- **Powering up with the cable plugged in = USB first**: you never boot into Bluetooth and have to press FN + 4.
- VBUS has 20 ms debounce, so plug wobble won't trigger it.

### 3.2 What happens when switching

- **USB and Bluetooth are never connected at the same time.** Switching to Bluetooth while plugged in makes the USB keyboard disappear from the host (the keyboard detaches from the bus); switching back re-enumerates.
- Before switching, the keyboard releases every held key, so you never end up with a stuck repeating key.
- **VIA only works on the USB channel** — over Bluetooth / 2.4G the device doesn't exist on the host. Press `FN + 4` to return to USB before remapping.

### 3.3 Status LED

There is no dedicated status LED; the **per-switch LED under the relevant key** is used instead (deliberately dimmed, indication only):

| Event | LED | Pattern |
| ---------------- | --------------- | -------------------------------- |
| Switched to Bluetooth / not yet connected | Under the matching number key (FN+1 → the `1` key) | **Blinks blue until connected** (no timeout) |
| Bluetooth connected | Same | **Solid for 1.5 s**, then back to the effect |
| Bluetooth dropped | Same | Back to blinking blue |
| Back to USB | Under the `4` key | Solid green for 3 s |
| Switched to 2.4G | Under the `5` key | Solid purple for 3 s |

> "Connected" gets its own solid blink on purpose: "stopped blinking" and "the indicator gave up" look identical, so users can't tell from a non-blinking LED whether they are actually connected.

## 4. Bluetooth

### 4.1 Three pairing slots

The keyboard remembers **3 hosts**, one per slot. A slot is not "the Nth device you paired" — the three slots are independent:

- Switching to a slot broadcasts with that slot's name: `czm_dc22_ble1` / `czm_dc22_ble2` / `czm_dc22_ble3`;
- Bonding info is stored in the keyboard (survives power loss), so **reconnecting the same computer needs no re-pairing** — switching to that slot reconnects automatically;
- Whichever slot is active shows as connected on that host; the other two show as disconnected.

> ⚠ **Work in progress**: switching slots only changes the broadcast name — directed reconnect to a specific host isn't implemented yet, so **any already-paired host** may connect. Per-slot directed reconnect waits on the "slot ↔ host address" table.

### 4.2 Pairing a new host

1. Hold `FN` and press `1` / `2` / `3` to pick a slot — the LED under that number key starts blinking blue;
2. In your computer's / phone's Bluetooth settings, find **`czm_dc22_ble1`** (or `2` / `3`) and connect;
3. The LED goes solid for 1.5 s and returns to the effect — connected, ready to type.

### 4.3 Re-pairing

`FN + 6`: the keyboard advertises "anyone can connect" for **30 seconds**. Useful for a new computer or when bonding info got messy. If no host connects within 30 s, advertising stops (saves power and keeps the keyboard out of other people's Bluetooth lists).

### 4.4 Known limitations

- **Media keys don't work**: volume / playback / calculator do nothing over Bluetooth. The stack's keyboard service has no consumer report; adding it means changing the HID report descriptor, scheduled after the basic channels are verified on hardware.
- **Idle disconnect**: Bluetooth disconnects after **60 seconds** of idle to save power; any key press reconnects.
- **Never verified on hardware**: everything above comes from the firmware code; the first hardware run may still need changes.

## 5. 2.4G wireless

**Work in progress.** `FN + 5` currently only switches the channel and lights the purple LED once — it produces no input; RF transmit and the USB receiver aren't done.

## 6. Remap with VIA

1. Connect the keyboard to the computer with a Type-C cable and press `FN + 4` to make sure you're on the **USB channel** (VIA only works over USB);
2. Open [usevia.app](https://usevia.app/) (or [via.micah.vip](https://via.micah.vip/));
3. Load this keyboard's JSON, then remap.

Keymaps are stored in the keyboard — **they survive power loss and moving to another computer**. `FN + PgUp` restores the factory keymap.

Besides regular keycodes, the VIA picker also offers this keyboard's own functions (VIA names):

| VIA name | Function |
| ---------------- | ---------------- |
| Mode USB | Switch to USB wired |
| Mode BT1 / BT2 / BT3 | Switch to Bluetooth profile 1 / 2 / 3 |
| BT Next | Next Bluetooth profile |
| BT Pair | Bluetooth re-pair |
| Mode 2G4 | Switch to 2.4G (work in progress) |
| NKRO | Toggle NKRO / 6KRO |
| Battery | Report battery level |
| LED Tog / LED + / LED - / LED Next | Lighting on-off / brightness up-down / next effect |
| Bootldr | Enter bootloader |
| Reset | Restore the factory keymap |

## 7. Lighting

- 22 per-switch LEDs, 49 effects; brightness / effect / speed / hue / saturation are all saved across power loss;
- Effects are switched in the **FN2 layer** (long-press `P/`);
- **Audio reactive** (listed as Audio Reactive in the effect list) is driven by a spectrum pushed from the PC — there is no microphone on the keyboard, so a PC tool has to run once; **USB channel only**.
